旋转小火锅合成测试数据集 v0.1

内容：6种候选菜品；本批实现小馒头和腌牛肉，2条连续轨迹、8张独立AI图片、8条称重观测。
图片由内置图像生成工具制作。所有重量、时间、事件均为人为设定的模拟值，不是实拍或实测。
精确克数是场景设定，不能由生成图片验证，也不应把本批当作真实视觉估重的标定集。
菜品难度是设计预期，尚未通过模型评测验证。

使用方法
1. 用浏览器打开 preview.html 查看两条轨迹，点击“查看答案”对照场景设定。
2. 程序按 timestamp 顺序读取 observations.jsonl，图片路径相对于数据集根目录。
3. 提供 dish_catalog.json 里的菜品绑定和截至当前时刻可见的 operation_log.jsonl。
4. answer_key.jsonl 只供评分，不能作为模型输入；后续帧和未来操作记录也不能提前提供。
5. 先测试质量检查、重量变化解释和事件识别。实际补菜量需要线上其他盘余量、需求速度、备菜时间和在途量，本批未虚构确定的补菜决策答案。

文件与字段
observations.jsonl：sample_id 唯一观测编号；sequence_id 轨迹；plate_id 物理盘；serving_id 本次装菜批次；dish_id 菜品绑定；timestamp 带时区的模拟时间；station_id 站点；lap_index 圈次；image_path 图片；tare_g 皮重；gross_weight_g 毛重；net_weight_g 毛重减皮重。
image_width / image_height 为实际文件像素尺寸，不代表图中有效清晰度；target_plate_location 指画面下半部主盘；previous_sample_id 与 observed_net_delta_g 仅由同盘前次观测计算。
answer_key.jsonl：scenario_net_weight_g 为设定净重；scenario_item_count 为设定数量（腌肉不适用时为null）；event_since_previous_observation 为上次观测到本次的事件；scenario_net_delta_g 为设定净重差（首帧null）；visual_condition / sensor_condition 为干扰标签；expected_behavior 为可接受的判断方向。
operation_log.jsonl：模拟员工上菜/补菜记录。按时间揭示，本批假设记录完整，但实际部署不能仅凭“无记录”证明没有补菜。
scenario_config.json：单位、噪声界限、站点时序和假设。
dish_catalog.json：6种候选菜品以及本批是否已实现。
generation_prompts.json：每张图片对应的完整提示词与参考关系。
image_manifest.json：图片对应的提示词键及文件校验值。

场景设定
两个盘子各有独立轨迹，A→B→C→A，每60秒到下一站，每180秒一圈。
相机模拟传送带侧面的低位斜拍，设计俯角约20度（未经几何标定），目标盘仅占画面一部分。
基准图也包含低清晰度、压缩感、噪点、运动模糊、邻盘和背景干扰；不使用清晰俯拍图作为本批输入。
同菜品序列保持相机和背景大致一致，暂不叠加站点视角差异。盘号由外部绑定提供，图中未生成可解码标签。
标注数量是模拟设定，不代表遮挡图片中可核实的数量；禁止要求模型在视觉证据不足时精确数出后排食物。
每盘皮重统一假设180克；正常称重误差不超过±2克；相邻两次正常读数最多可能相差4克而没有真实变化。
小馒头每个假设25克：8个200克→取走2个→6个150克；第三次读数人为注入+181克误差；第四次恢复。
腌牛肉300克→取走90克并摊平→遮挡但实际无变化→记录补充120克后为330克。
第一批仅覆盖称重正向突跳；负向突跳、漏测、重复记录、盘号错配、空盘和换菜留待扩展。

评估边界
这是可供演示和检查管道的微型样例，不是充分的训练集或独立测试集。
同轨迹图片基于参考图编辑，彼此高度相关；不要拆分到训练集和测试集。扩展后应按轨迹、场景、生成源分组划分。
答案中的事件原因是模拟设定；在线系统在证据不足时输出“疑似、待复核”是合理行为。
质量下降仅意味着盘内量减少，不等于顾客吃完，也不自动等于浪费。
图片未做像素级分割标注，肉片无数量标签；合成图片可能存在外观漂移，未宣称克数与像素严格对应。
这组图按用户反馈改为侧面低位斜拍，尚未依据真实安装位置、相机参数或现场截图标定。
