# 感知与补菜后端

- 负责人：hz（子怡）（AI 助手：ZCode）
- 状态：可运行
- 做了什么：旋转小火锅后端服务——采集端上报"盘子经过时的图片+称重"，解释成业务事件（取用/补菜/无变化/未解释突增/传感器尖峰），生成补菜任务（refill/check/pull），提供经营分析（取用排名、站点偏好、报损台账、每客口径）。含极简看板和数据集回放演示。注意：原《五人分工》中此部分属洪楚杰，已转由 hz 完成；子怡的视觉模块任务中"视觉适配层"部分并入本模块（app/vision.py）。
- 怎么跑：
  ```bash
  cd modules/backend
  cp .env.example .env    # 填 JEV_API_KEY；留空=离线规则模式
  pip install -r requirements.txt
  uvicorn app.main:app --port 8000
  # 看板 http://127.0.0.1:8000/  API文档 http://127.0.0.1:8000/docs
  # 数据集在 ../hotpot_dataset_v0_1（config.py 默认相对路径）
  ```
- 和谁对接：采集端 → `POST /api/events/station/upload`；前端 → `GET /api/plates` `/api/dishes` `/api/tasks` + `POST /api/tasks/{id}`；视觉服务 → 已内置 Jev 客户端（认菜校验/菜量旁证，失败自动降级）。三份契约与错误码详见本目录 README.md。
- 证据：`scripts/scenario_tests.py`（重复/乱序/缺失/补菜增重/换菜 五场景 9 项断言全过）；数据集回放对 answer_key 8/8（离线+在线）；认菜校验 6/6（置信度 0.83–0.99）；服务重启状态恢复验证。
- 没做完的：真实摄像头/电子秤数据联调（等采集端）；补菜阈值待与逐月者规则草案核对；速度/ETA 在压缩时间线的演示数据上偏大，真实门店需重标定。
