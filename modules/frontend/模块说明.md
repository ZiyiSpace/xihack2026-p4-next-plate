# 红考拉补菜与经营分析工作台

- 负责人：liiiyiiixiii（群昵称待确认）（AI 助手：Codex）
- 状态：可运行的独立原型；与团队后端联调未完成。
- 做了什么：实现厨房端和管理端，展示菜品余量、补菜任务、补充数量和到达补餐口倒计时。管理端包含任务操作、撤盘报损、经营分析、CSV 导出和门店规则配置。随页面一起归档原型自带的 API、确定性补菜规则及 D1 持久化，保证原型可独立运行。模拟与真实数据隔离，DeepSeek 配置支持服务端加密保存。
- 怎么跑：建议 Node.js 24，执行下方首次初始化；详细说明见 [README.md](README.md) 和 [docs/INTEGRATION.md](docs/INTEGRATION.md)。不包含本机数据库或密钥，首次运行必须初始化数据库和环境变量。

```sh
cd modules/frontend
npm ci
cp .env.example .env
# 在 .env 中设置 MODEL_KEY_ENCRYPTION_KEY：32 随机字节的 base64。
# 可用 node -e 'console.log(require("node:crypto").randomBytes(32).toString("base64"))' 生成。
npm run build
node --import ./scripts/sites-env.mjs node_modules/wrangler/bin/wrangler.js d1 execute DB --local --persist-to .wrangler/state --config dist/server/wrangler.json --file drizzle/0000_smooth_midnight.sql
node --import ./scripts/sites-env.mjs node_modules/wrangler/bin/wrangler.js d1 execute DB --local --persist-to .wrangler/state --config dist/server/wrangler.json --file drizzle/0001_wandering_jackpot.sql
npm run dev
```

访问 `http://127.0.0.1:5173/`，选择厨房端或管理端。DeepSeek 与采集令牌可按 README 配置；无需真实设备也可运行模拟演示。

- 和谁对接：当前页面调用本模块的 `/api/state`、`/api/actions`、`/api/analysis` 等，尚未调用 `modules/backend` 的 FastAPI 接口。团队后端契约以其 README 为准；下一步需要映射菜品/盘子/任务/分析接口、任务状态、ID 和错误响应。本原型规则与团队后端规则存在差异（例如噪声阈值、闭店限量、补菜增重判定），不能直接并行记账或宣称已完成集成。真实到口预测还需采集端提供 `refillArrivalAt`。
