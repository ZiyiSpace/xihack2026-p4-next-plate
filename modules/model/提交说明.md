### commit 1 — 修复工作台反代（**动了 `modules/backend/app/main.py`**）

打开 `http://127.0.0.1:8000/` 只能看到裸 HTML、一条样式都不生效。根因是 `_proxy_frontend` 有两处漏转发：

| 漏了什么 | 后果 |
|---|---|
| **`Accept`** | httpx 默认发 `Accept: */*`，Vite 据此把 `.css` 当 JS 模块返回 `text/javascript`（235,149 字节）；直连 `:5173` 时浏览器发 `Accept: text/css,...`，拿到的是 `text/css`（220,827 字节）。浏览器 MIME 检查拒绝套用样式。 |
| **查询串** | 路由是 `/{path:path}`，不含 query；Vite 的 `?v=<hash>` 模块版本丢失，模块图依赖版本错位。 |

修法：透传 `accept` / `user-agent` 与 `request.url.query`，并转发重定向的 `Location`（原来 308 不带 Location，浏览器跟不过去）。**26 增 9 删，只改了这一个函数。**

### commit 3 — 修复 `jev.py` 重试白名单失效（**动了 `modules/backend/app/jev.py`**）

代码评审时查出的既有 bug，不是这次新引入的：

```python
try:
    ...
    if r.status_code in (401, 422, 413):
        r.raise_for_status()        # ← 在 try 里抛
    ...
except (httpx.HTTPError, JevUnavailable) as e:   # ← HTTPStatusError 是 HTTPError 的子类
    last_err = e                                 # ← 又被抓住，继续重试
```

**`raise_for_status()` 抛的 `HTTPStatusError` 是 `httpx.HTTPError` 的子类**，立刻被同一个 `except`
抓住进入下一轮。所以文档里写的「401/422/413 不重试」**从来没有生效过**。

修法：状态码判断移出 `try`，只重试「可能自己好的错误」（transport 异常、5xx、408/425/429，
以及**该端点应当存在时**的 404）；其余 4xx 立即抛 `JevUnavailable`（`vision.py` 正是在等这个异常）。

### commit 4 — 删除重复的 Jev 客户端，拆分联调脚本
