### 顺带查出的一个既有 bug：`_post` 的重试白名单从来没生效

原 `_post` 是这么写的：

```python
try:
    ...
    if r.status_code in (401, 422, 413):
        r.raise_for_status()          # ← 这一抛是在 try 里面的
    ...
except (httpx.HTTPError, JevUnavailable) as e:   # ← HTTPStatusError 是 HTTPError 的子类
    last_err = e                                  # ← 于是又被抓住，照样重试
```

**`raise_for_status()` 抛的 `HTTPStatusError` 是 `httpx.HTTPError` 的子类**，所以它立刻被同一个
`except` 抓住，进入下一轮重试。文档里写的「401/422/413 不重试」**从来没有生效过** ——
错误密钥、404、422 全都会老老实实重试三次。

**已修**：把状态码判断移出 `try`，只重试「可能自己好的错误」（transport 异常、5xx、
408/425/429，以及**该端点应当存在时**的 404）。其余 4xx 立即抛 `JevUnavailable`。

实测：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| `/v1/portion`（端点不存在） | 24.9 s（3 次请求） | **8.4 s（1 次请求）** |
| `/v1/measure`（端点不存在） | 30.5 s（3 次请求） | **10.1 s（1 次请求）** |
| 错误密钥 → 401 | ≥10.5 s（纯退避）+ 3 次往返 | **4.7 s（1 次往返）** |

服务器侧计数确认：调一次 `/v1/portion`，`api.log` 里 `POST /v1/portion` **只 +1**（107 → 108）。

## 五、顺带发现的两个问题（不在本模块，未改动）

1. **后端在 Windows 上起不来。** `core.py:49` 用 `json.load(open(...))` 读
   `dish_catalog.json`，没指定 `encoding="utf-8"`；Windows 默认 GBK，遇到 UTF-8 中文
   直接 `UnicodeDecodeError` 崩溃。Linux 上没事（默认 UTF-8），所以 hz 那边测不出来。
   - 临时绕过：设环境变量 `PYTHONUTF8=1`（本模块两个脚本都自带这个设置）。
   - **正确修法**：给那些 `open()` 加 `encoding="utf-8"`（一行）。
2. **`.gitignore` 没忽略 `.venv`**（本轮刚补了 `node_modules/`、`dist/`、`.wrangler/`、`.next/`、`*.log`，
   但漏了 `.venv`），谁在仓库里建虚拟环境都会变成未跟踪文件。
