# 集成与联调（后端 ↔ Jev 视觉服务器）

- 负责人：chujieHong（AI 助手：DeepSeek Harness）
- 状态：**可运行** —— 两个脚本都能直接跑，已产出实测结果

## 做了什么

把 `modules/backend`（业务规则）和 `modules/model`（Jev 视觉服务器）之间的联调**做成可复跑的脚本**，
而不是靠人肉点看板。两个脚本分工不同：

| 脚本 | 测什么 | 什么时候用 |
|---|---|---|
| `check_jev_contract.py` | **单端点**：后端要用到的每个 `/v1/...` 还在不在、通不通、返回能不能用 | 服务器重启/换地址/改版本之后 |
| `run_online_replay.py` | **整条链路**：起真实后端 → 在线回放数据集 → 报对评分数与耗时 | 演示前、改动后端之后 |
| `check_workbench_render.mjs` | **页面真的渲染了吗**：真开浏览器打开工作台，等卡片出现，确认图不是裂图 | 改前端、改图片链路之后 |

`check_workbench_render.mjs` 只依赖 Node 内置的 `fetch` / `WebSocket`（Node 22+），
浏览器按 `CHROME_EXE` → Edge → Playwright 缓存的 chromium 顺序自动找：

```bash
node modules/integration/check_workbench_render.mjs http://127.0.0.1:8000/admin
```

它读的是 `naturalWidth`——只有图片**真的解码成功**才会大于 0，
光比对 `<img src>` 看不出裂图。反例（拿入口页 `/` 跑）会退出 1 并指出
「卡片 .capture-panel 没渲染出来」，不是恒真的检查。

关键点：两个脚本都**用后端自己的 `app.jev.JevClient`**，不是 curl。
`jev.py` 有自己的重试/超时/离线降级逻辑，用真实客户端测，测的才是真实联调路径。

## 怎么跑

```bash
# 依赖：后端 requirements（fastapi / uvicorn / httpx / python-multipart）
pip install -r modules/backend/requirements.txt

# 密钥从环境变量读，不要写进仓库
JEV_API_KEY=jev_xxx python modules/integration/check_jev_contract.py
JEV_API_KEY=jev_xxx python modules/integration/run_online_replay.py --mode online

# 离线对照，不需要密钥
python modules/integration/run_online_replay.py --mode offline
```

退出码：契约自检 `0`=全通 / `1`=有缺口 / `2`=没给密钥；回放 `0`=对评满分。

## 和谁对接

| 方向 | 谁 | 什么 |
|---|---|---|
| **依赖** | `modules/backend` | 直接 import 它的 `app.jev.JevClient`、`app.config`，并静态扫描它的 `app/*.py` |
| **依赖** | `modules/model` | 打它的线上服务器；`hotpot_dataset_v0_1` 提供自检图 |
| **给** | 全队 | 接口变更的早期预警：后端在用、服务器没有的端点会被直接列出来 |
