# PR 说明（分支 `feat/virtual-capture`，基于 `main` = `a2c262b`）

**标题建议**：无硬件数据接入：虚拟采集端 + 抓拍图片链路 + 管理端一键上传样例

14 个提交，47 个文件，+3261 / −46，与 `main` 无冲突。

## 为什么

项目要做「相机拍盘 + 称重台读数 → 后端判读 → 补菜策略与人群分析」，但手上没有硬件。
已有的 `POST /api/replay` 是**进程内直调 service** 的自检回放，不是设备侧的东西：
它绕过 HTTP、没法交给别人跑，也证明不了接口真的通。另外图片只写盘、
**没有任何 HTTP 出口**，前端完全拿不到采集画面。

这个 PR 补上「设备那一侧」这个缺失的角色，让图片真正可读，并给了三条把数据弄进来的路。

## 数据进来的三条路

| 方式 | 适合 | 位置 |
|---|---|---|
| **管理端上传** | 手上有几张图，想立刻看结果 | 管理端 → 门店设置 → 数据接入 → 选图 → 填净重 → 点运行 |
| **命令行采集端** | 数据多、要反复跑、要交给别人 | `modules/simulator`（只走 HTTP，不 import 后端代码，只用标准库） |
| **数据集模板** | 想按自己的图批量造数据 | 复制 `modules/simulator/dataset_template/` |

三条路都走**同一个站点事件接口**，不另开旁路——所以数据进来之后，
总览的余量、台账、补菜任务、分析页的时段统计全都自动带上它。

## 主要内容

**后端**
- `images.py`（新）：抓拍图片存储。上传 / 按名读取 / 列目录；事件的 `image_ref` 从
  宿主绝对路径改成同源 URL；按内容嗅探 MIME（JPEG 被存成 `.png` 也不会返回错的类型）。
- `samples.py`（新）：样例数据接入。上传、登记、识别、按菜品自动分盘入账。
- `vision.identify_dish()`（新）：纯识别（「我不知道这是什么菜」），
  与既有的 `check_binding`（「验证是不是我以为的那道菜」）分工不同。
- `db.get_recent_captures()`、`images.key_of()`、`HotpotService.reset()`、
  `POST /api/maintenance/reset`。

**前端**
- `capture-card.tsx`（新）：工作台「采集抓拍」卡片——最近一张图 + 称重 + 规则判读 + 模型识别结果。
- `sample-intake.tsx`（新）：门店设置 → 数据接入的样例上传区。
- `lib/reading.ts`（新）：判读词汇与格式化的唯一来源。

**联调与验收**
- `check_workbench_render.mjs`：真开浏览器确认卡片渲染，且图片 `naturalWidth > 0`（不是裂图）。
- `check_sample_intake_flow.mjs`：从界面选图、填净重、点运行，核对取用量与补菜任务。

## 修掉的 bug

1. **【既有】工作台「待补充」数量常年翻倍。** `analytics.dish_summaries` 里两段逐字相同的
   在途量累加，在售菜品被加两遍。实测：任务 50 克（折合 2 个）→ 工作台显示 **4 个**。
   后厨会照错数备料。
2. **`PATCH /api/samples` 不校验**：`observed_at:"garbage"` 能存进来，入账时才炸成 500。
   现在非法值在入口就是 422。
3. **批次中途出错 → 数据库与登记状态不一致**：一条坏数据让整批 500，已入账的事件留在库里、
   登记状态却还是「待运行」。现在单条隔离，逐条记住结果。
4. **自动分盘与手填盘号撞车**：手填 P001 + 另一道菜留空时 P001 会被发两次，两菜混进同一 serving。
5. **改完输入重跑显示「已入账」但结果全空**：事件按编号幂等被忽略却不自知。现在如实说明，
   并给了「复位并重跑」。
6. **样例登记表借用通用 `meta` 表**：`reset_all` 会顺手删掉用户上传的样例，已独立成
   `data/samples.json`，并给读-改-写加了锁。
7. 图片落盘的 `.part` 残片可被下载、并发写共用同一临时文件、`event_id` 无格式约束却被当文件名。
8. 前端：时刻格式化 3 份、判读说法 2 份、克数格式化 2 份 → 各收成 1 份；
   「首次上盘基准」被 `||"watch"` 画成黄色告警 → 改为中性。

## 需要 reviewer 注意的取舍

**采集端默认把整条时间轴平移到当前时刻（`--shift now`）。** 不这么做的话，数据集时间戳
（2026-10-03）进去后，后端拿真实当前时间与事件时间作差，算出「几小时没有取用」，
每一盘都显示滞留需复核。平移之后才是这个场景该有的样子。代价与关闭方式写在
`modules/simulator/模块说明.md` 里，不是隐藏行为。
